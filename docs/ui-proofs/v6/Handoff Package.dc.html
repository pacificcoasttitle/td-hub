Reports & Farming PDFs

Implementation spec for four report types: one list page, one modal, one delivery log and three print documents. The design mocks are the picture and this is the translation. Every reference below was read from main.

Superseded since 17 Sep. Follow the code on these two: (1) Concierge list wording has no credit language. It reads Property lookup / Failed before the lookup / Failed after the lookup, and a test enforces it. (2) Delivery: green means proved delivered via the event webhook, and SendGrid acceptance reads as Sent (migrations 0060–0061). Wherever this document says "1 credit", "no credit charged" or "delivered", read it that way.

Two decisions that must survive translation. They are cheap now and expensive later, and both are the kind that get quietly dropped.

1 · Notify rep ≠ Send to agent. Notifying the branded rep that a report exists and delivering it to an outside agent are different acts. Only the first is in scope. Do not name it "Send".

2 · The log row is written in the same transaction as the attempt. Including failures. A send that cannot write its log row is not sent. The prelim path has the opposite rule — logging never blocks a send — and recorded 1 delivery out of 1,083.

Part A · Reports list page

Route: /reports in the admin shell (the SidebarNav app, not (hub) or (sales)). Add to NAV in src/components/admin/sidebar-nav.tsx as a kind:'link' entry after Documents. Permission via the existing allowedPaths mechanism.

Component: clone the structure of src/components/admin/contacts/company-type-list-page.tsx. Everything except the columns and the filter values is that file: p-6 wrapper, text-2xl font-semibold text-[#1A1A2E] title with text-sm text-[#6B7280] mt-1 subtitle, Add New button (bg-[#1B2A4A] … rounded-lg with the plus svg), debounced 300 ms search, segmented filter, right-aligned count, bg-white rounded-lg border border-gray-200 shadow-sm table card with bg-gray-50/60 head and divide-y divide-gray-100 body, and the pager. PAGE_SIZE = 25.

Two departures from the pattern, both deliberate

  • Filter values. Active / Inactive / All is meaningless for a report. Same control, values All / Farming / Concierge.
  • Subject and Settings are two columns, not one. This is the only new idea on the screen and the reason one table holds four types. Subject is always the place or property — the thing an agent recognises. Settings is always the type-specific parameters. Never merge them.

Layout: use table-layout:fixed with declared column widths and truncate on Report / Subject / Settings / Branded To. With seven columns, table-layout:auto lets un-wrappable content push Actions off-screen — that cost four iterations in the mock.

Data: one GET /api/reports?page&pageSize&type&search returning a union across the four report tables, sorted created_at desc, each row stamped with its type — the shape getSalesAllReportData() produced in legacy. Include the latest delivery per report so the Delivery cell needs no second fetch.

Part C · Delivery log

Build this with the table, not with the send. Nothing depends on the reports table yet, which makes it the cheap place to get right.

ColumnPurpose
report_type + report_idWhat was delivered
kindnotify_rep today; send_to_agent later without a migration
recipient_name, recipient_emailA rep today, an agent contact later — same two columns
sent_byActing user
attempted_atOf the attempt, not of the success
outcome, outcome_detaildelivered / failed + the provider's reason
payload_modeattachment or signed_link, and the link's expiry

Write rule. One row per attempt, in the same transaction as the attempt, failures included. If the log write fails, the send fails. Not best-effort, not fire-and-forget, not a queue that can drop.

Read rule. The Delivery column derives from this table. Never denormalise to a sent boolean on the report row — a flag and a log disagree eventually, and then neither is trusted.

Never sent reads differently from delivered. Silence looking like success on every screen anyone checked is the actual failure being designed against.

No permanent public link. Legacy wrote these PDFs to S3 with public read and emailed the raw URL; the URLs are guessable and the reports carry property and sales data. Deliver as an attachment or a short-lived signed link. render.ts already keys PDFs per render under concierge/{id}/profile-{timestamp}.pdf and serves them through our own route — follow that, and record which mode was used.

Part D · The three farming PDFs

The most important sentence in this document: the hub does not render PDFs from HTML. Legacy went HTML → wkhtmltopdf; the hub uses @react-pdf/renderer via renderToBuffer, as in src/lib/domain/concierge/render.ts. So Farming Reports Family.dc.html is a picture of the intended output, not a template. It cannot be dropped in, and lifting its CSS would fail in ways that only show on the page.

The pattern to follow: profile-document.tsx

Build the three as sibling modules to document/profile-document.tsx, reusing its conventions exactly:

  • Shell component — one <Page size="LETTER"> per page with the navy masthead bar and a fixed footer carrying "Page X of Y". This is the shared masthead and footer the family needs; it already exists.
  • TEMPLATE_VERSION — stamp it on every generated row so an old PDF is always tied to the template that made it. Bump on layout change.
  • No flex gap. react-pdf's layout engine ignores it. Use marginRight on every tile plus a tileLast override — the comment in that file records the bug this caused.
  • Font.registerHyphenationCallback((w) => [w]) — without it "LOS ANGELES" renders as "LOS ANGE-LES". These reports are full of city names.
  • Absences are rendered, never filled. GAP = '—' for a missing value, the Absent box for a missing section, with a sentence saying why. Applies directly: a city with no condo sales gets an em dash, not a zero.
  • The fmt helpers — money, moneyShort, numf, year, sqft, dt. Note year is deliberately separate so a year can never gain a thousands separator. Reuse them; do not write new ones.
  • Charts via react-pdf Svg primitives (Rect, Line, SvgText), as PriceChart does — not a charting library.

Tokens: take the document's, not the mock's

The mock uses Instrument Sans with #16324F / #C86A2A. The real document component uses Helvetica with NAVY #1B2A4A, ORANGE #F26B2B, MUTED #526174, BORDER #D7DDE5, TINT #F8F9FA. Use the document component's values. That makes all four artefacts genuinely one family rather than approximately one, and it is the reason to translate rather than port.

One deliberate divergence: profile-document.tsx sets body text at 8.5pt with 6pt tile labels, which suits a reference document read at a desk. These three are leave-behinds handed across a table. Set body 9.5pt, table cells 8.5pt, tile labels 7pt minimum. Nothing below 7pt.

Shared footer — the one thing profile-document doesn't have

The concierge profile lists the presenting rep as key-value rows. These three are branded leave-behinds: the rep's photo, name, title, phone and email sit in an identical block on every page of every report. Build it once as a RepFooter component shared by all three.

  • Photo is a react-pdf <Image> from a data URI loaded out of our own S3 — follow loadImage() in render.ts. Legacy's checkRemoteFile HTTP HEAD does not come across.
  • A rep with no photo renders the block without it. Never a placeholder silhouette.
  • Customer service (866) 724-1050 · cs@pct.com and openorders@pct.com on all three — legacy varied this per report for no reason.

Report 1 · Sales Activity

One page. Six headline tiles in two rows of three (three navy, three tinted), then a month-by-month table, newest first.

ElementValueDataset field
TilesHomes sold · median sale price · median $/sq ft · typical bedrooms · typical bathrooms · owned by non-occupants %count, median(price), median(price/area per sale), median(beds), median(baths), share(ownerOccupied = false)
TableMonth · sales · median price · median $/sq ft · changeGrouped by calendar month within the window
Changevs the previous month in the window, one decimal, em dash on the oldest rowNot year-over-year

Legacy's month filter matched month-number regardless of year, so a 12-month run ignored the year entirely. The dataset window must be a real date range.

Report 2 · Carrier Route Analysis

One page. Six standout tiles, then ten routes ranked by the chosen metric.

ElementValue
Standout tilesFastest turnover · most non-owner occupied · longest held · largest mail drop · most sales · highest median price
TableRoute · turnover · non-owner · yrs held · units · sales · median price
DefinitionsThree one-line explanations under the table: turnover, non-owner, units. Agents read these, not analysts

Defect fixed, not ported: each standout tile prints the route that won its own metric. Legacy's "Highest Non-Owner" tile printed the turnover winner's route beside the non-owner percentage. Compute each tile from its own field.

Route ids arrive as ZIP+route concatenated (904031C001) and print hyphenated (90403-1C001) — legacy's separateZipRoute() logic. Standouts are the best of the ten shown, not of the whole file; say so on the page.

Report 3 · County Sales

Multi-page, 22 cities per page, alphabetical, case-normalised. Two column groups — Houses (navy header) and Condominiums (orange header) — each with Sold and Median price, plus a county total row on the last page.

Defect fixed, not ported: the column says Median and legacy computed the mean. The label was right, so the maths changed. Every price in the family is a true median, including price per foot, which is the median of each home's own rate rather than a ratio of two sums.

This is the one constraint on the data source. A median cannot be computed from pre-averaged city figures, and neither can an honest county total. County Sales needs per-sale rows. If SiteX Farms only ever delivers city-level averages, the median label cannot be honoured and the defect has been rebuilt with better typography. Establish the shape of that feed before this report is built.

Naming, everywhere

Three names, used in the class, the route, the list label, the page masthead and the email subject, with no aliases: Sales Activity, Carrier Route Analysis, County Sales. Legacy had SalesActivityReport generating the County report, the list label "Sales Activity" meaning the Snapshot, and the two email subjects swapped. The class that generates County Sales is named for County Sales.

Dataset contracts, not CSV contracts

Each report reads a named dataset. CSV upload is one producer; SiteX Farms will be another. Nothing in the documents changes when the second arrives — which only holds if the dataset, not the file, is the interface.

DatasetShapeRow
Area salesPer-sale rows + area name, window, type filterprice, floor area, beds, baths, sale date, owner-occupied, property type

Property type must collapse to a known set. Legacy counted only rsfr and rcon after lowercasing, so Condo and SFR were silently dropped while RCON and RSFR worked — the subtitle promised new homes that no column could hold. Unrecognised types must be reported as a count, not discarded in silence.
